# Lezo-AI — تسجيل دخول + ذكاء اصطناعي

مشروع ويب عربي جاهز للنشر على Railway، مبني على واجهة Lezo-AI الأصلية، مع حسابات مستخدمين وربط OpenRouter من خلال Backend آمن.

## المميزات
- تسجيل حساب جديد وتسجيل دخول بالبريد الإلكتروني وكلمة المرور.
- تخزين الحسابات في PostgreSQL، وكلمات المرور تُخزّن كـ hash باستخدام bcrypt.
- جلسة دخول داخل Cookie من نوع HttpOnly بدل وضع رمز الدخول في JavaScript.
- اتصال فعلي بـ OpenRouter من السيرفر؛ مفتاح API لا يُرسل إلى المتصفح.
- حفظ سجل المحادثات محليًا في المتصفح لكل حساب على هذا الجهاز.
- تصميم عربي RTL متجاوب، مظهر فاتح/داكن، سجل محادثات، ورسائل خطأ واضحة.
- تحديد معدل محاولات تسجيل الدخول والطلبات إلى الشات.

## نشر المشروع على Railway

### 1. ارفع ملفات المشروع إلى GitHub
1. فك ضغط `Lezo-AI-Railway.zip` على جهازك.
2. أنشئ مستودعًا جديدًا على GitHub.
3. ارفع محتويات المجلد إلى جذر المستودع؛ يجب أن يكون `package.json` في الجذر، وليس داخل مجلد إضافي.
4. لا ترفع ملف `.env` ولا مفتاح OpenRouter أبدًا. ملف `.env.example` مجرد مثال بلا مفتاح حقيقي.

### 2. أنشئ خدمة التطبيق
1. افتح https://railway.com/ وسجّل الدخول.
2. اختر إنشاء Project ثم Deploy from GitHub Repo وحدد مستودع Lezo-AI.
3. Railway يكتشف تطبيق Node.js من `package.json` ويستخدم `npm start`.

### 3. أضف قاعدة بيانات PostgreSQL
1. من لوحة المشروع اضغط **New** ثم **Database** ثم **PostgreSQL**.
2. افتح خدمة التطبيق (وليس خدمة قاعدة البيانات) ثم **Variables**.
3. أضف متغير `DATABASE_URL` واجعل قيمته مرجع Railway إلى قاعدة البيانات، غالبًا:
   `${{Postgres.DATABASE_URL}}`
   إذا كان اسم خدمة قاعدة البيانات مختلفًا، استخدم الاسم الظاهر في مشروعك.

### 4. أضف الأسرار وإعدادات التطبيق
في **Variables** لخدمة التطبيق، أضف هذه المتغيرات:

| الاسم | القيمة |
|---|---|
| `OPENROUTER_API_KEY` | مفتاحك السري من OpenRouter |
| `OPENROUTER_MODEL` | `openrouter/auto` أو معرّف نموذج متاح في حساب OpenRouter |
| `JWT_SECRET` | سلسلة عشوائية طويلة وفريدة، لا تقل عن 32 حرفًا |
| `NODE_ENV` | `production` |

لا تضع مفتاح OpenRouter في `index.html` أو `js/app.js` أو في مستودع GitHub. أضف المتغيرات من لوحة Railway فقط. يمكنك توليد قيمة عشوائية لـ `JWT_SECRET` باستخدام مدير كلمات مرور موثوق.

بعد إضافة المتغيرات، نفّذ **Deploy** أو أعد النشر. السيرفر ينشئ جدول المستخدمين تلقائيًا عند بدء التشغيل.

### 5. أنشئ رابطًا عامًا
في خدمة التطبيق، افتح **Settings → Networking → Generate Domain**. افتح الرابط الذي ينشئه Railway؛ ستظهر شاشة تسجيل الدخول. أنشئ حسابًا ثم ابدأ المحادثة.

## التشغيل محليًا (اختياري)
تحتاج Node.js 20+ وقاعدة PostgreSQL. انسخ `.env.example` إلى `.env`، ثم ضع بيانات قاعدة البيانات والمفتاح والأسرار في `.env` المحلي فقط. لا ترفع `.env` إلى GitHub.

```bash
npm install
npm start
```

ثم افتح http://localhost:3000 .

## نقاط مهمة
- لا يوجد حساب افتراضي؛ المستخدم ينشئ حسابه بنفسه.
- إنشاء الحسابات وتسجيل الدخول يحتاجان قاعدة PostgreSQL شغالة.
- استخدام OpenRouter قد يستهلك رصيدًا أو يخضع لحدود حسابك؛ راجع نموذج التسعير والرصيد في حسابك قبل الاستخدام.
- اختيار النموذج الافتراضي `openrouter/auto` قابل للتغيير من متغير `OPENROUTER_MODEL` على Railway.
- سجل المحادثات محفوظ في المتصفح الحالي فقط، وليس في قاعدة البيانات؛ مسح بيانات المتصفح قد يمسحه.
- زر إرفاق الملفات يعرض أسماء الملفات فقط حاليًا؛ لا يرفع محتوى الملفات إلى النموذج.
- لا يوجد استرجاع كلمة مرور بالبريد في هذه النسخة.
- راقب استهلاك API وأضف حدودًا مالية في OpenRouter، ولا تشارك مفاتيحك مع أحد.
